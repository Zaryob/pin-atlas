# Adding a verified board or MCU

1. Identify the exact board revision, fitted MCU and package. Record physical connector positions separately from MCU pad numbers. Group a board with an existing layout only after matching its connector geometry; keep power nets and processor functions reference-specific.
2. Add source records to `sources/manifest.json`: stable ID, publisher, revision, source URL, view URL, cache filename and SHA-256. Pin GitHub sources to a full commit. A GPIO table must be the dependency named by the package XML, including shared tables with a different chip name.
3. Use `sources/stm32-catalog.json` for supported STM32 sources: `nucleo64` records UM1724 table page/index locations; `nucleo32` selects UM1956 model pages; `nucleo144` records explicit manual, drawing, Zio and Morpho tables; `blackpill` names verified WeAct CAD variants; `packages` adds standalone chips. Use `partNames` for exact part suffixes and reuse shared GPIO documents through `gpioModesDocument`. Other layouts require a source-specific builder; do not reinterpret an existing board's geometry.
4. Extract original source facts. If CI needs a PDF-independent path, record raw source cells, pin both the original PDF and extraction hashes, and compare the original and recorded parsing results. Never use generated board assignments as source snapshots. Document manual errors with independent evidence.
5. Run `python3 scripts/verify-official-sources.py --table-snapshots --write`, `npm run build:data`, then `npm run check`. Profiles must satisfy `sources/board.schema.json` and the shared catalog contracts, including valid board-to-MCU net/pad links. The runtime compiler validates full shared geometry before generating the small catalog and content-addressed profile/evidence bundles.
6. Register a new physical layout in the appropriate platform’s `layouts` list in `public/catalog.mjs`; every verified profile in that layout becomes an individual model card. Do not add compatibility-only aliases as verified models. Add English-first labels with Turkish translations. Add hardware-specific assertions and verify search, pin selection, board/package navigation and saved-plan compatibility on desktop and mobile.
7. Run `python3 scripts/audit-source-downloads.py --document SOURCE_ID` for each added document. This deliberately ignores local caches. Review generated data, evidence, verification totals and the CSV together; commit and push the completed addition.

The weekly **Audit source downloads without cache** workflow detects remote availability and revision changes without making deployment depend on the ST CDN. Its artifact records attempted URLs and hashes. Failed availability checks require investigation; hash mismatches require a deliberate source review, never an automatic lock update.

`sources/legacy-h723-pin-ids.json` preserves old plan IDs; it is migration configuration, not source evidence. Its contacts are checked against the new manual tables and its electrical identities against the old pinned variant. Preserve the existing ID-to-signal relationship when extending any published profile; corrections to unsupported functions must retain old browser entries with a visible warning.

Hardware controls are generated in `scripts/hardware_sources.py` from locked manual tables, board circuits and pinned IOC signals. Describe explicit states and cite their evidence; use `unknown` when the physical state has not been declared. Effects may reserve an entire electrical net or only a disconnected contact. Routed contacts must reuse a verified source contact's functions and MCU pad, retain physical IDs and declare any pads that must remain floating. Do not infer clone wiring or silently assume factory settings. Hardware metadata belongs in lazy profile bundles, not the startup catalog.

Test each control's routes, unavailable functions, coupled pads and saved-plan restoration. Configured records and JSON/share payloads use v2 with pins and settings together; preserve v1 backups and preview cancellation. Pin suggestions consume the configured board and the central plan validator. Extend peripheral parsing only for documented names and bus identities; verify partial locked connections, AFIO compatibility, distinct instances, occupied/shared pins and bounded-search outcomes.
